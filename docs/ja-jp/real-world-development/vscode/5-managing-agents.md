Copilot をエージェント モードで使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行を自律的に行います。VS Code の Copilot Chat では、自分のコンピューター上での作業がリアルタイムに進むため、ツールの呼び出しやファイルの編集を確認できます。差分をインラインでレビューして変更ごとに採用または却下し、フォローアップのプロンプトでエージェントに方向を伝えたり、作業を広げたりできます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして採用します。
- 作業中のエージェントに指示し、ハイ コントラストに加えてライト モードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタムエージェントが、ハイ コントラスト モードを実装しています。作業中に、デザインチームから追加の要望がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライト モードの切り替えも追加してほしいとのことです。新しい会話を始めるのではなく、既存のセッションに指示して作業を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが調べたファイル、実行したコマンド、提案した編集が順番に表示されます。編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 から Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツールの呼び出しを確認します。ファイルの読み取り、編集、実行を求めるターミナル コマンドが表示されます。
3. ファイル編集が提案されたら、差分がチャット内に表示されます。
   - **Keep** を選ぶと変更を採用します。
   - **Undo** を選ぶと変更を元に戻し、別の方法で作業するようエージェントに依頼します。
4. Chat ビューの上部にある **Files changed** を開くと、セッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナル コマンドの実行などで許可が必要な場合、エージェントは一時停止して **Allow** を表示します。許可するコマンドを確認してください。

5. エージェントがハイ コントラスト モードを実装し終えるまで待ちます。最後に、変更内容の概要が表示されます。

## ライト モードを追加するようエージェントに指示する

ハイ コントラスト モードができたら、同じ会話でライト モードの切り替えも追加します。同じチャット セッションを続けることで、エージェントは編集した component、スタイル、local storage の使い方を含むこれまでのコンテキストを保てます。

1. Copilot Chat の入力欄に次のフォローアップ プロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントは既存の変更を調べ、ライト モードの変更を提案します。
3. ハイ コントラストのときと同じように、新しい編集を確認し、差分ごとに **Keep** または **Undo** を選択します。
4. 望まない方向に進んだ場合 (たとえば、気に入らない方法で toggle UI を再構成しようとした場合) は、チャット入力欄の隣にある **Stop** で停止し、補足のメッセージを送信します。

> [!TIP]
> 作業中のセッションに指示する方が、最初からやり直すより早く済みます。フォローアップで変更を依頼します (「CSS を簡潔にして、selector の重複ではなく CSS variable を使ってください」)、方向を修正します (「3 つ目の toggle を追加せず、既存の設定パネルにライト モードを統合してください」)、または範囲を広げます (「両方の toggle にキーボード ショートカットも追加してください」)。

## 作業セットをレビューする

commit する前に、エージェントが変更したすべてのファイルを確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro component、スタイル、関連テストが更新されています。
3. いくつかのファイルを開いて差分を確認します。ARIA 属性、キーボード操作、semantic HTML、local storage への保存など、カスタムエージェントのアクセシビリティ パターンが反映されていることを確認します。
4. 問題がなければ **Source Control** パネルから変更を stage して commit します。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェント モードを使って、作業中のセッションを監視して方向付けました。ファイル編集を確認して採用または却下し、コンテキストを失わずに作業を拡張するフォローアップ プロンプトを送信しました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- ファイル編集を個別に採用または却下しました。
- 作業中のセッションに追加の指示を送りました。

[次のレッスン][next-lesson]では、アクセシビリティ作業をプルリクエストとして公開し、このラボでローカルのカスタムエージェントが行った変更をレビューします。
